# JENIOS R76.001 — Saúde real do host R74 no painel

Registro: 27/10/2026. Base imutável R75: commit 05f622b249c0d41814a0af47a9fff050005293d8.

## Diagnóstico
O painel administrativo R73, recuperado e publicado em R75, preserva um texto histórico “WAITING_FOR_SOURCE” mesmo depois da instalação do serviço R74. O runtime R74 possui heartbeat real no Supabase, mas processa ciclos sintéticos; não transmite ordens Paper nem reais. Os valores last_heartbeat_at, last_cycle_at e contadores foram conferidos em leitura pelo servidor, mantendo live_execution_enabled=false.

## Entrega R76
- REST exclusivo GET /api/platform/admin/robots/host-health.
- Proteção herdada da R73: projeto JENIOS correto, branch de produção correta, quatro gates operacionais false, token do Auth exclusivo Platform e permissão platform.admin no banco dedicado.
- Consulta server-side de metadados mínimos da tabela jenios_robot_private_hosts_r74, sem código privado, host ID, identidade de cliente, token, posição ou credencial.
- Estados informativos SYNTHETIC_ACTIVE, STALE, DEGRADED, UNVERIFIED e NOT_CONFIGURED. O último heartbeat e ciclo são confrontados com o horário do servidor; dados de configuração ou ordens contraditórios exigem revisão.
- Novo cartão dentro da administração dos robôs existente, recarregado somente por comando do administrador, com limpeza de dados após logout/troca de conta e novo getSession antes de exibir os dados.
- Retorna execução certificada=false, conta de corretora verificada=false, custódia=false e nenhuma permissão para ordens reais.
- QA Preview exige bancos e 20 flags externas explicitamente bloqueadas. A fonte G49 e a recuperação R75 são preservadas por SHA no manifesto R76.

## Aceite técnico
Tests contra Auth simulado e leitura simulada de metadados: 401/403/404/405, erro de banco, heartbeat obsoleto, futuro, estado inconsistente, não vazamento de segredo, isolamento e documentação do guard de QA.
Build geral, regressões S05, smoke GET web e API bloqueada não autenticada, hash da fonte e commit de origem. Testes reais em dispositivo ainda dependem de sessão de administrador.

## Limites e continuidade
Isto não implementa adaptador de ordens, POST de corretora, autenticação de conta externa, teste Paper, cobrança, assinatura, alteração de banco ou Trade Live. Os robôs continuam operando exclusivamente em modo sintético, sem custódia. Cliente final usará conta própria por API/terminal oficial quando o executor e o risco forem homologados.
